# Paketo Buildpacks

## Introduction

- Paketo provides production-ready buildpacks for the most popular languages and frameworks, transforming application code to container images
- These containers can run on Docker and Kubernetes
- Buildpacks are used by VMWare Tanzu
  - Tanzu encourages using `Pack CLI` for local development whereas it uses `kpack` for its production system
  - The images created either way are same

## Installation

- Paketo Pack CLI is available as a docker image
- We can also manually install Pack CLI on WSL from https://github.com/buildpacks/pack/releases
  - installed the `pack-v0.40.1-linux.tgz`, extracted it and then ran `sudo mv pack /usr/local/bin/`
  - now `pack --version` tends to work
  - this expects a Docker API version 1.51 but our Docker API version is 1.41
    - you can check the docker API version using `docker version` and finding the API version
    - we can run `export DOCKER_API_VERSION=1.41` to fix this

## Building images

- Buildpacks need a few images to work
  - builder
  - run-image
  - lifecycle
- To build an image with Pack Docker, use 
  - `docker run -v /var/run/docker.sock:/var/run/docker.sock -v $PWD/workloads/springweb:/workspace -w /workspace f95 build k8s-pck-springweb:0.0.1 --builder <builder-image> --run-image <run-image> --lifecycle-image <lifecycle-image>`
  - here `f95` is the paketo image id
  - we dont really need to pull the builder image though as the above automatically does it but works either way
- To build an image with Pack CLI, use
  - `pack build k8s-pck-springweb:0.0.1 --builder <builder-image> --run-image <run-image> --lifecycle-image <lifecycle-image> > ../../log.log`
  - use this in the same directory as the project so `cd workloads/springweb`
- This will try to detect type of project, and should find Maven for spring web
  - this detection will fail if your Java project is a WAR with the provided scope tomcat dependency
    - make it a JAR project, remove the dependency and remove ServletInitializer.java which is only required for WARs
  - then it attempts to find an older version of the image, but its fine if it doesn't find it for the first build
  - then it attempts to install Java from Github, so we need to point to an internal mirror like artifactory or add a proxy if behind firewall
    - add `--env HTTP_PROXY=<proxy-address> --env HTTPS_PROXY=<proxy-address>` to the pack build command
  - need to also create a binding for the custom `settings.xml` as shown where the type file says `maven` and the other file is the `settings.xml`
  - in the pack build, we have to include a volume option like `--volume $PWD/bindings:/platform/bindings` (not as a `-v` option when using the docker-pack build)
